# Automated reliability evidence

This milestone adds a **measured** experiment runner that writes `results.json` and `report.md`. The files are generated by the workflow and attached as GitHub Actions artifacts; this repository does not contain fabricated performance figures.

## Automated CI run

The **Reliability experiment reports** workflow starts the Docker lab, submits ten synthetic baseline orders, stops Kafka, observes the API response, restarts Kafka, and measures time to the first accepted order. It uploads results as a workflow artifact, even if a later assertion fails.

Run it manually from GitHub Actions using **Run workflow**, then download `reliability-experiment-results`.

## Local baseline and outage

```bash
docker compose up --build -d
python3 scripts/experiment_suite.py --count 10 --broker-outage
```

**Warning:** Broker outage intentionally stops the local Kafka service. Use only in your own disposable Compose lab.

## Optional HTTP latency comparison

```bash
docker compose --profile experiments up --build -d
python3 scripts/experiment_suite.py --count 10 --latency
```

The runner creates an 800ms Toxiproxy downstream latency toxic, collects baseline and degraded request samples, then removes the toxic in a `finally` block.

## Analysis checklist

Record host specifications and image versions, inspect Prometheus and Jaeger, compare median/p95 latency, explain failure and recovery semantics, and note any anomalous results. The small sequential sample is an illustrative experiment, **not** a statistically defensible throughput benchmark.
